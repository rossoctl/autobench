AutoBench Service {{ .Values.image.tag | default .Chart.AppVersion }} installed as {{ .Release.Name }} in namespace {{ .Release.Namespace }}.

Requires Rossoctl v0.8.0 or later on this cluster. An older operator accepts the Service's deploy
request and silently drops fields from it, so the benchmark runs in a shape you did not configure.

This chart does NOT create the instance-config Secret {{ .Values.instancesSecret }} — it holds ROPC
service credentials and is generated out-of-band. Without it the pod stays unready:

    kubectl -n {{ .Release.Namespace }} get secret {{ .Values.instancesSecret }}

    # if absent, on OpenShift:  reference/ocp-service-bootstrap.sh --cluster <name> ...
    #             on kind:      reference/kind-service-bootstrap.sh
{{ if (include "autobench.llmProfile" .) }}
This release declares llmProfile={{ include "autobench.llmProfile" . }}, so the instance file must
carry that profile's gateway. Generate it with the matching selector and check them against the live
cluster:

    reference/{ocp,kind}-service-bootstrap.sh --llm-profile {{ include "autobench.llmProfile" . }} ...
    python3 reference/preflight.py --llm-profile {{ include "autobench.llmProfile" . }} --context <ctx>
{{- else }}
No llmProfile is declared for this release, so nothing can check that the instance file's gateway is
the one whose key table issued the key in openai-secret. A mismatch does not fail at deploy: it 401s
per completion, mid-run, and the leg finishes with zeroes. Set llmProfile to intranet or internet.
{{- end }}

{{ if .Values.ibacJudge.enabled }}
The IBAC judge is part of this release, so `helm uninstall {{ .Release.Name }}` removes it. Two things
it does NOT remove, both on purpose:

  * secret/{{ .Values.ibacJudge.upstreamSecret }} — a credential, installed out-of-band, so delete it
    by hand if this cluster is done with benchmarking. The proxy reads it once at pod start:

        kubectl -n {{ .Release.Namespace }} rollout restart deploy/{{ include "autobench.judgeName" . }}
{{- if .Values.ibacJudge.managePlatformConfig }}
  * nothing in configmap/{{ .Values.ibacJudge.platformConfigMap }} permanently: the post-install hook
    recorded that ConfigMap's original ibac.judgeEndpoint/judgeModel in
    configmap/{{ include "autobench.judgeName" . }}-prior, and the pre-delete hook writes them back.
    Do not delete that record by hand — without it, uninstall leaves the fields pointing at a judge
    that no longer exists. Check the patch landed:

        kubectl -n {{ .Release.Namespace }} get cm {{ .Values.ibacJudge.platformConfigMap }} \
          -o jsonpath='{.data.config\.yaml}' | grep -A6 '^ibac:'

    A `helm upgrade` of the ROSSOCTL release re-renders that ConfigMap and reverts the patch. The
    plugin then goes inert with no error — every tool call admitted, the legs still pass — so re-run
    `python3 reference/preflight.py --plugin-legs ...` after any platform upgrade.
{{- else }}
  * configmap/{{ .Values.ibacJudge.platformConfigMap }}'s ibac fields — managePlatformConfig is false,
    so nothing points the plugin at this judge yet and it stays INERT: it admits every tool call and
    the legs still pass. Set them yourself, or set managePlatformConfig=true.
{{- end }}
{{- end }}
Verify the rollout, then the API:

    kubectl -n {{ .Release.Namespace }} rollout status deploy/{{ include "autobench.name" . }}
{{- if and (eq (include "autobench.platform" .) "openshift") .Values.route.enabled }}

    HOST=$(oc -n {{ .Release.Namespace }} get route {{ include "autobench.name" . | trimSuffix "-service" }} -o jsonpath='{.spec.host}')
    curl -fsS "https://$HOST/healthz"
{{- else if and (eq (include "autobench.platform" .) "kind") .Values.httpRoute.enabled }}

    # 8080 is the HOST port kind publishes the istio gateway on — not this Service's port.
    curl -fsS http://{{ .Values.httpRoute.hostname }}:8080/healthz
{{- else }}

    kubectl -n {{ .Release.Namespace }} port-forward svc/{{ include "autobench.name" . }} 18080:{{ .Values.service.port }}
    curl -fsS http://127.0.0.1:18080/healthz
{{- end }}

/benchmarks and /deploy need a caller bearer token; /healthz does not. Remember the list endpoint
returns `items`, not `benchmarks`, and only summarises each benchmark — read
GET /benchmarks/<name> to see an agent's container_image, extra_env or model_override.
